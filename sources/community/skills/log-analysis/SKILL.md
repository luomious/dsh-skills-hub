# Log Analysis（日志分析）

用证据链还原事件，区分「现象、根因、猜测」，输出可执行的排查结论。

## 分析流程

1. **确认范围**：日志来源（应用/系统/网络）、时间范围、已知触发操作；日志可能涉敏，不把完整内容外泄。
2. **时间线还原**：按时间戳排序关键事件；识别「先导事件 → 异常 → 后果」的因果链。
3. **异常聚类**：同一错误去重归并（按错误签名：类型+关键参数），统计出现次数/频率/首次与最后出现时间。
4. **根因定位**：对每个异常类回答——
   - 触发条件是什么（输入/状态/时序）
   - 错误是根因还是被上游拖累的连带现象（看它出现前的 5-20 条日志）
   - 能否用日志中的证据证实（时间戳、上下文行、堆栈）
5. **输出结论**：区分「已证实」「高度可能」「需补充证据」三级，不要臆测。

## 输出格式

```
## 排查报告
- 时间范围 / 数据量 / 异常总数
## 时间线（关键事件，按时间排序）
## 异常聚类
### 异常 A（次数 / 频率）
- 签名: ...
- 首次: ... 最后: ...
- 根因: ...（证据: 引用的日志行）
## 结论与建议
- 根因（1-3 条，按可信度标注）
- 修复/处置建议（可执行步骤）
- 待补充证据（如需）
```

## 注意事项

- 引用日志时**原样摘录关键行**（可截断超长行），不要转述改写导致失真。
- 时间戳跨时区/无时区时先统一换算并注明假设。
- 大日志优先用过滤/抽样/统计，避免整段粘贴；明确告知用户分析覆盖了哪些范围。
