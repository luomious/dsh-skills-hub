# Code Review（系统化代码审查）

按固定流程审查代码，先通读再逐层检查，输出可执行的分级报告。

## 审查流程

1. **理解意图**：先读改动说明/commit message/相关上下文，明确这次改动想解决什么问题、影响哪些模块。
2. **通读改动**：按 diff 顺序读一遍，记录疑问点，不急于下结论。
3. **分层检查**（每层都要过）：
   - 正确性：边界条件、空值/未定义、并发与竞态、异常路径、错误处理是否吞掉
   - 安全：注入（SQL/命令/路径/模板）、鉴权缺失、敏感信息泄露（密钥/日志）、越权
   - 性能：不必要的重复计算、N+1 查询、大对象拷贝、无界增长（缓存/队列/内存）
   - 可维护性：命名、魔法数字、重复代码、函数过长、模块耦合、注释与文档是否同步
   - 风格：与项目既有约定的一致性（格式化/命名/导入顺序）
4. **验证假设**：能静态确认的用静态证据；需要运行验证的明确列出验证步骤，不要凭空断言。

## 输出格式

```
## 审查结论
总体评价（1-3 句）+ 统计（严重/建议/风格 各 N 条）

## 问题清单
### [严重/建议/风格] 标题
- 位置: 文件:行号（多个位置用列表）
- 问题: 一句话说明根因
- 影响: 触发条件与后果
- 建议: 具体修改方案（可给出代码片段）
```

- 每条问题必须有**位置 + 根因 + 建议**，缺一不可；不确定的问题标注「需确认」并说明证据缺口。
- 没有问题时明确说「未发现明显问题」，不要为了凑数硬写。
- 严重问题（缺陷/安全/数据丢失风险）必须放在最前面并醒目提示。
